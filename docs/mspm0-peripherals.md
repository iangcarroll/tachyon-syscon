# MSPM0 peripheral model boundaries

`tools/mspm0/peripherals.py` uses the pinned TI register metadata and peripheral headers in `references/ti-mspm0`. It is a deterministic digital model for executing the original firmware. Its time unit is an emulator instruction, not a measured MCU clock cycle. The supported register names do not imply complete simulation of every feature in those peripheral blocks.

The peripheral tests exercise public MMIO operations and external inputs through the real `MCU` object. The original firmware reset, copied RAM flash executor, application loop, UART CLI, CONFIG persistence, and injected I2C NACK tests provide integration coverage without original-function hooks. These are local software tests; no board is accessed or flashed.

## Register state and reset

Ordinary writes use SVD field masks. PWREN and RSTCTL require the documented keys; key fields are not retained. Peripheral reset clears its FIFO/conversion/transaction state, and the reset-sticky flag is set or cleared separately. Resetting a peripheral never resets the external I2C expander itself. Undefined write-only reads still stop unless the scenario supplies an explicit fixture. The original GPIO ICLR read remains such a fixture; it is not generalized to other write-only registers.

`Devices.reset_system('sysresetreq')` resets peripheral registers and in-flight operations, retains the four SYSCTL shutdown-store bytes, and preserves external inputs and the expander. The core separately preserves SRAM, flash, factory data, and NONMAIN. SYSCTL `RSTCAUSE` is read-to-clear; unread lower reset-cause identifiers take precedence. WWDT reset reports `SYSWWDT0`. The `por` scenario clears shutdown stores but does **not** model power sequencing or boot ROM. Unknown reset causes stop. RESETCMD accepts the SYSRST key/GO combination; BOOTRST/BSL/POR command paths stop at an explicit unsupported boot-domain boundary.

The retention distinction follows the SYSCTL RESETLEVEL description (SYSRST resets CPU and peripherals) and shutdown-store PMU register layout. This is a modeled reset-domain boundary, not evidence that the full chip power-reset sequence has been reproduced.

## Interrupts and GPIO

Raw interrupt flags are independent of both peripheral masks and NVIC enable bits. Peripheral output levels are passed to `MCU.set_irq_line`; clearing a peripheral source does not erase an already latched NVIC pending bit. Shared sources are ORed. CPUSS group 0 uses WWDT0 slot 0, FLASHCTL slot 3, and SYSCTL slot 6; group 1 uses GPIOA slot 0. The group index is slot plus one, and group reads do not clear the originating peripheral source. The mapping is from the [MSPM0L1306 datasheet, Table 8-6](https://www.ti.com/lit/ds/symlink/mspm0l1306.pdf). DEBUGSS and EVENT subscriber sources are not generated by this model.

`set_gpio_inputs(value, mask)` drives external GPIO levels and records configured rising, falling, or both-edge flags on pins not driven as outputs. GPIO DOUT/DOE atomic aliases update the same backing registers, and DIN combines external inputs with enabled outputs. This boundary does not simulate pin mux electrical routing, pulls, filtering, voltage levels, or analog edge timing.

## UART and I2C

UART receive honors module/power/RXE enable, character versus four-entry FIFO mode, and RX FIFO threshold selection. Overflow drops the new byte and sets the overrun flag (bit 4), not the transmit flag. RXDATA drains FIFO order, updates threshold state, and rejects an empty read. IIDX returns and clears the highest-priority flag. TX requires module/power/TXE enable and appends to an immediate external sink.

UART transmission timing, TX FIFO backpressure, baud rate, receive timeout, framing/parity/break detection, DMA, and flow control are not yet modeled. In particular, an instantaneous TX sink must not be used as evidence that transmitter underrun/overrun behavior has been verified. Incoming bytes must be explicitly paced by a scenario.

The existing expander bus model is reused for synchronous I2C transactions; NACK now raises raw interrupt status even while both interrupt masks are disabled. It remains a digital protocol model with explicit NACK/stuck controls, not an electrical bus or full I2C controller implementation.

## ADC

Only software-triggered unsigned 12-bit single and finite sequence conversions across the four physical memory registers are accepted. Manual mode holds the sampling phase while SC is high and starts conversion when SC is cleared. Automatic mode starts on the SC rising edge. Conversion completion updates the ULL and SVT result aliases, BUSY, and MEMRES interrupt flags. Clearing ENC lets the current conversion finish and aborts the remaining sequence. Missing or out-of-range channel samples stop rather than silently filling a value. `adc_stuck` prevents completion; `adc_delay` is an explicit virtual delay.

Repeated conversion, hardware triggers, averaging, other resolutions, and signed output stop as unsupported. Analog sample-and-hold, reference settling, ADC clock selection, and calibration are not simulated. Inputs are explicit digital samples, read at conversion completion.

## Flash controller

The MAIN flash transaction validator is shared with the low-level oracle, but MCU completion is **time driven**, not dependent on how often software reads status. CMDEXEC schedules a command; no flash mutation occurs before execution or completion. Supported commands are 1 KiB sector erase, 8-byte program, and 8-byte blank check. Protection, alignment/range checks, write masks, NOR 1-to-0 constraints, busy state, terminal error status, and DONE interrupt are modeled. Reset aborts an in-flight mutation. `flash_stuck` and the existing controller failure selector support negative controls. `flash_delay` controls virtual completion time.

The model uses the SVD reset values. Tests set protection registers explicitly; the separate low-level oracle's initial all-protected fixture is not evidence of chip reset state. Bank erase, NONMAIN programming, ECC, wear, supply failures, and execution stalls caused by flash-bus contention are not modeled. The old isolated FLASHCTL oracles retain their scripted status-read completion behavior and were not globally changed.

## Watchdog

A valid first WWDTCTL0 write starts the watchdog. Restarting requires exactly `0xa7`; invalid register keys and closed-window feeds request a WWDT system reset. Window 0/1 selection and all closed-window fractions are represented. Interval mode emits periodic interrupts instead of reset. RUN and documented read-as-zero counter restart behavior are modeled. Reinitializing an already configured watchdog stops as unsupported rather than pretending a new configuration took effect.

Startup behavior is independently supported by TI's [MSPM0L11XX/L13XX DriverLib WWDT documentation](https://software-dl.ti.com/msp430/esd/MSPM0-SDK/1_30_00_03/docs/english/driverlib/mspm0l11xx_l13xx_api_guide/html/group___w_w_d_t.html) and [its initialization source](https://software-dl.ti.com/msp430/esd/MSPM0-SDK/1_30_00_03/docs/english/driverlib/mspm0l11xx_l13xx_api_guide/html/dl__wwdt_8h_source.html): initialization consists of a keyed WWDTCTL0 write. Key and window fields come from pinned `hw_wwdt.h`.

The default virtual watchdog clock ratio is 1000 instruction ticks per LFCLK tick and is configurable. This is not oscillator timing validation. Sleep gating with STISM stops pending explicit POLICY/clock-domain support. Full ESM routing, external reset signaling, and all hardware reset/clock interactions remain outside this model.
